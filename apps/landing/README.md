# Vitals

Your company's vital stats and decisions, living next to your knowledge base, measured
by your AI agent. A portable company operating dashboard you import into any business
project: one JSON-style config file per company, one zero-dependency renderer shared
across all of them, and Claude as the agent that keeps the config in sync with the codebase.

It is an internal tool, not a product (yet). Dogfood it on your companies. If other
founders ask "can I use that," that is the signal to spin it out (the Basecamp moment).

## What is in here
- `vitals.core.js` - the framework-agnostic renderer (UMD: a plain `<script>` and an import both work).
- `vitals.css` - styles, scoped under `.vitals` so they never touch a host app.
- `index.html` - the standalone shell (open it, no build step).
- `vitals.data.example.js` - the starter template. Full field reference in `schema.md`.
- `react/Vitals.jsx` - a React/Next wrapper around the same core.
- `bin/init.mjs` - vendors the dashboard into a target repo.
- `SKILL.md` - how Claude operates it (the interview and the commands).

## Three ways to use it

**1. Any project (static, React, Next, anything), one line:**
```
npx github:adamtpang/summon.company#installer
```
Run it from inside the project (or pass a target path). It vendors the dashboard into
`vitals/` and drops a starter `vitals.data.js`. Then open `vitals/index.html`, or serve
the folder. In a Claude Code session you can just say "add vitals to this project" and
Claude runs that one line, then "interview me" to populate it.

The `installer` branch keeps this small vendorable package at the repository root while
`master` contains the full summon.company engine monorepo. Both live in the same GitHub repo.

**2. React or Next project (import as a component):**
```jsx
import Vitals from "vitals/react";
import "vitals/style.css";
import { vitalsData } from "./vitals.data";   // your data object
export default function Ops() { return <Vitals data={vitalsData} />; }
```

**3. Vanilla JS (import the core):**
```js
import Vitals from "vitals";   // or: const Vitals = require("vitals")
const el = document.getElementById("app");
el.classList.add("vitals");
el.innerHTML = Vitals.render(data);
```

## For AI agents (machine-readable)
The site is agent-readable: [summon.company/llms.txt](https://summon.company/llms.txt) is the
index (install steps, operating loop, doc links) and
[summon.company/llms-full.txt](https://summon.company/llms-full.txt) inlines everything -
SKILL.md, schema.md, and the starter config - in one fetch. Any visitor can paste this
into Claude Code (or any AI coding agent):

> Read https://summon.company/llms.txt and give this repo a Vitals CEO dashboard, then interview me to fill it.

`llms-full.txt` is generated by concatenating `llms.txt` + `SKILL.md` + `schema.md` +
`vitals.data.example.js` - regenerate it after editing any of those.

## The Claude workflow (the point)
Open an AI coding session in the repo and talk to it:
- "interview me" to populate Vitals from the repo's context files.
- "log this week", "check off <milestone>", "set <metric> to N", "add a decision".
Claude edits `vitals.data.js`; refresh the dashboard. The codebase is the knowledge
base, the data file is the state, and Claude is the runtime.

## Privacy
Finance numbers live in `vitals.data.js`. If they are real and sensitive, add
`vitals/vitals.data.js` to that repo's `.gitignore` so they stay local.
