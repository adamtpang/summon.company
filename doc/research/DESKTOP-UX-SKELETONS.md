# Desktop UX Skeletons — What Summon Should Steal, Skip, and Ship

**Research date:** 2026-07-15
**Scope:** UX anatomy of the two agent-console incumbents (Claude Desktop, Codex/ChatGPT desktop) plus 15 evidenced workspace patterns (Linear, Superhuman, Slack, Figma, Raycast, Obsidian, Notion, Devin, Height), mapped onto Summon's existing surfaces (formation view, roadmap view, issue chat threads, agent detail, costs/quota panels) and queued work (VIT-37 model picker, VIT-40 conversation continuity, VIT-41 per-employee messaging, usage monitoring).

**Framing:** Summon is not an IDE. The human is the **board**, not the driver. Claude Desktop and Codex are consoles for a *developer supervising code agents*; Summon is a console for a *founder supervising an AI company*. The skeleton comparison below tells us what the state of the art looks like; the adoption list translates it up one management level.

**Bottom line of the comparison:** the two incumbents have converged on the same six-piece skeleton — (1) sidebar of parallel work units with status, (2) composer with model+effort+permission controls adjacent to send, (3) usage rendered as ring/meters not numbers, (4) worktree isolation per parallel task, (5) notify-only-when-unfocused-work-finishes-or-blocks, (6) diff-centric review with inline comments. Summon should treat all six as table stakes and differentiate on the layer neither has: **persistent employees with roles, a company-level decision queue, and board-grade (not developer-grade) reporting.**

## 2. The 10 Features Summon Should Adopt

### 1. The decision queue: triage inbox with one-key verbs
- **What:** A single queue containing *only items that need a human decision* — approvals, blocked runs, questions, completed work awaiting review. Every item resolves with one keystroke.
- **Who does it best:** Linear Triage (1=accept, 2=duplicate, 3=decline, h=snooze; nothing enters the real backlog without explicit human accept — a built-in trust boundary; snoozed items return on date OR new activity) — [linear.app/docs/triage](https://linear.app/docs/triage). Superhuman proved the game-loop feel of one-key verbs — [writing.arman.do/p/superhuman](https://writing.arman.do/p/superhuman). Codex's Running/Waiting-for-approval states are the agent-native version.
- **Summon mapping:** This is a **new surface — the Inbox** — and it should be the app's home screen. Sources: agent approval requests (from claude_local/codex_local permission prompts), completed issue runs, agent questions, quota warnings. Verbs: `1` approve, `2` request changes (opens comment-on-diff), `3` reject, `h` snooze, `e` archive-to-receipts. Issue chat threads (existing) become the *detail* pane of an inbox item, not the entry point. This is also the drain-rate governor: if the queue grows faster than the board drains it, the console should say "run fewer employees" (Codex community guidance, [nimbalyst](https://nimbalyst.com/blog/how-to-run-multiple-codex-agents-in-parallel/)).

### 2. Two-pane review that never navigates away
- **What:** Queue list stays in the left column while the focused item's full detail (thread, diff, output) renders right; j/k moves through the list; all verbs work without opening anything.
- **Who does it best:** Linear Inbox (j/k scroll the list, right column shows the focused issue, act without navigating) — [linear.app/docs/inbox](https://linear.app/docs/inbox).
- **Summon mapping:** The Inbox from feature 1 gets this layout. Reviewing employee output must never lose the board's place in the queue. The right pane reuses the existing **issue chat thread** component; the left list reuses issue cards from the roadmap view.

### 3. Employee presence: status dot + live "what I'm touching" line
- **What:** Every employee shows an ambient state (working / idle / blocked / done-awaiting-review) plus one live line of what they're touching right now (file, issue, URL).
- **Who does it best:** Figma multiplayer — presence (avatars, named cursors) creates trust that work is happening without anyone reporting it — [figma.com/blog/multiplayer-editing-in-figma](https://www.figma.com/blog/multiplayer-editing-in-figma/). Devin Desktop's "Agent Command Center" kanban (status, task progress, PR readiness per session) is the agent-native precedent — [devin.ai/desktop](https://devin.ai/desktop/). No app yet renders AI presence as dots+cursors — open territory (workspace research, Pattern 7 gap).
- **Summon mapping:** Upgrade the existing **formation view** from a static roster to a live board: each employee card = avatar + state dot + current issue + one-line activity ("editing `pricing.ts`", "waiting on your approval — 12m") + a usage sparkline. This is Summon's signature screen; it's what makes the product feel like a company and not a terminal multiplexer.

### 4. Model + effort picker adjacent to send, switchable mid-run (**VIT-37**)
- **What:** Model dropdown and a separate effort/reasoning selector sitting next to the send button; changing either applies from the next response; keyboard menus with digit-select.
- **Who does it best:** Both incumbents, identically placed — Claude ([help](https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings)): Cmd+Shift+I / Cmd+Shift+E, digits 1–9. Codex ([models](https://learn.chatgpt.com/docs/models)): slider-style effort with a usage warning on the top tier.
- **Summon mapping:** VIT-37 ships this in the issue-thread and per-employee-chat composers. Two Summon-specific twists: (a) the picker sets a **per-employee default** (a junior employee runs the cheap model; the picker in a thread is an override), and (b) copy Codex's warning pattern — selecting the max tier shows projected cost against the employee's remaining quota before applying.

### 5. Usage ring per employee + dual company meters (queued: usage monitoring)
- **What:** Ambient per-unit usage (a ring next to the picker: context % + plan %) plus a panel with a 5-hour rolling window and a weekly/monthly cap rendered as progress bars; graceful wall behavior (in-flight turn finishes).
- **Who does it best:** Claude's usage ring next to the model picker + `/usage` breakdown by skill/subagent/MCP ([docs](https://code.claude.com/docs/en/desktop)); Codex's shared local+cloud pool with both meters applying simultaneously and let-the-turn-finish semantics ([pricing](https://learn.chatgpt.com/docs/pricing)).
- **Summon mapping:** The existing **costs/quota panels** get three levels: ring on every employee card (formation view) and composer; per-employee breakdown on **agent detail** (spend by issue, by tool, by model — Claude's `/usage` dimensions); company roll-up in the costs panel against the $99/employee/mo economics. When an employee hits its wall: let the current turn finish, park the employee as "resting until [time]" in formation view, and drop one digest item in the Inbox — never a modal.

### 6. Permission mode as a per-employee trust attribute
- **What:** A small set of named permission presets, selected per work unit and remembered; escalations arrive as approval cards with Allow once / Always allow / Deny; every "always" grant is reviewable and revocable in one panel.
- **Who does it best:** Claude — mode remembered per folder, per-task modes for scheduled work, revocable "Always allowed" panel ([docs](https://code.claude.com/docs/en/desktop), [scheduled](https://code.claude.com/docs/en/desktop-scheduled-tasks)). Codex — named **custom permission profiles** + Reviewing/Approved/Denied/Aborted/Timed out statuses ([approvals](https://developers.openai.com/codex/agent-approvals-security)).
- **Summon mapping:** On **agent detail**, permission mode is part of the employee's role card: e.g. *Intern* (read-only/plan), *Employee* (auto-accept edits, ask for commands/network), *Trusted* (auto with classifier checks). Escalation requests flow to the Inbox as approval cards with the three-way choice; "Always allow" grants accumulate on the agent detail page like a visible track record — which literally is the trust-building mechanic of an employee earning autonomy.

### 7. Transcript density control: Summary mode as the board's default (**VIT-40**)
- **What:** One toggle over the same thread: Normal (tools collapsed) / Verbose (everything) / Summary (final responses only); cycle with one key.
- **Who does it best:** Claude's Transcript view dropdown, with Summary explicitly recommended "for scanning many parallel sessions" ([docs](https://code.claude.com/docs/en/desktop)). Dispatch's contract — "it messages the outcome (spreadsheet, memo, PR), not process steps" ([help](https://support.claude.com/en/articles/13947068)) — is the same idea as a messaging norm.
- **Summon mapping:** Issue chat threads and VIT-41 per-employee chats default to **Summary** — the board sees outcomes; Verbose is one keypress away for audits. This also derisks VIT-40: conversation continuity stores the full event log once, and density is a render-time filter, so "continuity" and "readability" stop being competing requirements.

### 8. Dispatch-style router: message the company, not a config form (**VIT-41**)
- **What:** One persistent conversation where the human types a task in natural language; the system routes it to the right worker/surface, badges the spawned work with its origin, and pushes a notification when done or blocked — reporting outcome, not process.
- **Who does it best:** Claude Dispatch — persistent thread in Cowork's left panel, routes dev work to a Code session (which appears in the sidebar with a "Dispatch" badge), phone push on done/needs-approval ([help](https://support.claude.com/en/articles/13947068)).
- **Summon mapping:** VIT-41's WhatsApp-style messaging should ship **two chat types**: per-employee DMs (talk to one employee, full history — the WhatsApp part) and a **#company channel** that is Dispatch: "get a pricing page up" → routed to the right employee by role, issue auto-created on the roadmap, badge links the issue back to the originating message. This makes messaging the *assignment* surface, with formation/roadmap as the *monitoring* surfaces.

### 9. Worktree-per-run isolation with explicit promotion
- **What:** Every parallel run gets an auto-created git worktree; output is promoted deliberately ("Create branch here"), never landed silently; setup scripts handle untracked files (.env, node_modules).
- **Who does it best:** Codex — `$CODEX_HOME/worktrees/`, detached HEAD, ~0.8s creation, "Create branch here" in the thread header, Handoff between Local/Worktree ([verdent](https://www.verdent.ai/guides/codex-app-worktrees-explained), [official](https://developers.openai.com/codex/app/worktrees)). Claude matches with `.claude/worktrees/` + `.worktreeinclude` ([docs](https://code.claude.com/docs/en/desktop)).
- **Summon mapping:** The claude_local and codex_local adapters both inherit native worktree support — Summon's job is the **console contract**: an issue run shows which worktree it lives in, the diff-stats chip ("+12 −1") on the issue card, and a "Promote to branch / open PR" action that is a board decision (an Inbox item), never automatic. This is the mechanism that makes running 5+ employees on one repo safe.

### 10. Cmd+K command palette as the universal verb surface
- **What:** Ctrl/Cmd+K opens a palette; focus lands in the input; fuzzy subsequence matching tolerates sloppy queries; context-aware commands; every command displays its shortcut (the palette doubles as the teaching surface).
- **Who does it best:** Linear (canonical), Raycast (number-key selection, sub-100ms feel) — [mobbin.com/glossary/command-palette](https://mobbin.com/glossary/command-palette), [raycast.com/blog/a-technical-deep-dive-into-the-new-raycast](https://www.raycast.com/blog/a-technical-deep-dive-into-the-new-raycast). Demand proof: GitHub removed its palette July 2025 and reversed within five days after backlash.
- **Summon mapping:** Every console action reachable from the palette, including company-level verbs neither incumbent has: "assign [issue] to [employee]", "pause all employees", "summon [role]", "set [employee] model to [X]", "show costs this week". Full verb list in §4.

## 3. The 5 Anti-Patterns to Avoid

### 1. Invisible autonomy (the Height 2.0 death)
Height 2.0 pitched "autonomous project management" — auto bug triage, backlog pruning, spec updates happening without a visible human loop — and shut down 2025-09-24 ([businesswire launch](https://www.businesswire.com/news/home/20241008197812/en/), [retrospective](https://skywork.ai/skypage/en/Height-App-The-Rise-and-Sunset-of-an-AI-Project-Management-Pioneer/1975012339164966912)). The surviving agent-native pattern is Devin's visible session kanban with human checkpoints. **Rule for Summon:** every employee action is attributable to a visible run in the formation view, and nothing crosses a trust boundary (merge, publish, spend) without landing in the Inbox first. Market "employees you manage," never "automation you trust blindly." (Caveat: Height's cause of death is inferred from retrospectives, not founder-confirmed — but the design lesson holds independently.)

### 2. Interrupt-for-everything notifications
Slack's tier system (interrupt only for DMs/mentions/keywords; badge the rest; digest for catch-up; rate-limited urgency override) is why users keep its notifications on ([slack.com/help](https://slack.com/help/articles/201355156-Configure-your-Slack-notifications)). An agent console has 10× the event volume of a chat app; if progress updates interrupt, the user disables notifications entirely and the approval loop dies. **Rule:** interrupt ONLY when an employee is blocked on human input; completed work badges the tray/Inbox; everything else waits for the digest. If an employee can escalate past DND, rate-limit it like Slack (once per day).

### 3. An approval queue that grows unbounded
Codex practitioners converged on: "if the needs-review queue grows faster than you can drain it, run fewer sessions" ([nimbalyst](https://nimbalyst.com/blog/how-to-run-multiple-codex-agents-in-parallel/)) — the practical failure mode of parallel agents is that "wait for the agent" becomes "wait for me to finish reviewing." A console that lets you summon 20 employees but gives the board no drain-rate feedback manufactures guilt, then churn. **Rule:** show queue depth and average time-to-decision in the Inbox header; when depth exceeds a threshold, the console itself should suggest pausing hiring — a WIP limit on the company, not the code.

### 4. A console that waits on the network
Linear's local-first sync engine (IndexedDB as a real client DB, optimistic writes, background WebSocket sync, <50ms page loads) is why it reads as native-grade quality ([sync engine deep dive](https://www.fujimon.com/blog/linear-sync-engine)); Raycast holds the same bar with millisecond latency and number-key selection. **Rule:** Summon's own UI must never show a spinner — cache all console state locally (employees, issues, threads, quotas) and stream the agent event log in the background. Agents may be slow; the console may not. Users read speed as quality, and a "game console" that lags is a broken game.

### 5. IDE cosplay — shipping developer-density chrome to a board member
Claude's 8 drag-and-drop panes, integrated terminal, and SSH targets exist because its user is a developer mid-keystroke. Summon's user is reviewing outcomes. Copying pane sprawl, raw terminals, and verbose-by-default transcripts imports the incumbents' complexity without their audience — and destroys the two anchors users actually riot over losing: spatial stability and keyboard reachability (Slack's 2023 rail-removal backlash forced a partial restore, [tidbits](https://tidbits.com/2023/09/21/how-to-restore-the-slack-workspace-sidebar/); GitHub's palette reversal). **Rule:** fixed three-region layout, Summary-mode transcripts, diffs and terminals available but one level down (inside agent detail), and never relocate the left rail's sections once shipped.

- **Inbox (home):** two-pane. Left: queue list (approval cards, completed runs, questions, quota events) with j/k + one-key verbs (`1` approve, `2` request changes, `3` reject, `h` snooze, `e` archive). Right: focused item detail — the issue chat thread in Summary mode, diff chip expandable to a diff viewer with click-line-to-comment → Cmd+Enter resubmits to the employee (Claude's comment-on-diff loop). Empty state is a celebration: "All employees unblocked — nothing needs you" (NN/g win-state, [nngroup](https://www.nngroup.com/articles/empty-state-interface-design/)).
- **Formation:** kanban of employee cards grouped by state (Working / Blocked on you / Idle / Resting-at-quota). Click card → agent detail. First-run empty state ships one sample employee mid-task with one pending approval, so the very first screen teaches the review loop (Notion demo-data pattern, [pencilandpaper](https://www.pencilandpaper.io/articles/empty-states)).
- **Agent detail:** tabs — *Thread* (full DM history, density toggle Normal/Verbose/Summary, Ctrl+O cycles — VIT-40), *Activity* (run log, worktrees, promote-to-branch actions), *Trust* (permission profile, accumulated "always allowed" grants, revocation), *Usage* (spend by issue/tool/model), *Config* (default model + effort — VIT-37, adapter, role/system prompt).
- **Issue thread:** existing surface; gains the composer anatomy below and becomes embeddable as the Inbox right pane.
- **Composer (everywhere):** one consistent anatomy mirroring both incumbents — input, then adjacent to send: **model picker · effort selector · permission mode · usage ring**. All switchable mid-run.
- **Files as truth:** every employee's memory, logs, and deliverables persist as plain Markdown/files in the repo the user can open in anything (Obsidian's "file over app," [stephango.com/file-over-app](https://stephango.com/file-over-app)) — Summon's NORTH_STAR.md-driven layout already matches; market it as a trust feature.

### 4.3 Tray behavior (Windows-first)

- Close button hides to tray; app keeps running employees; launch on login. (Slack/Discord convention.)
- **Tray icon color encodes aggregate state:** green = all employees working/idle, amber = decisions waiting (count in tooltip), red = employee blocked or adapter down. Single left-click opens the Inbox.
- Per Microsoft's guidance the tray is for **status, not commands** — no critical-action context menu; the taskbar button remains the primary window control ([learn.microsoft.com](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)).
- Toast notifications follow the three-class taxonomy (Codex): *needs permission* and *has a question* interrupt; *turn/run completed* badges the tray only; daily digest ("what your employees did") renders as a Slack-Catch-Up-style card deck with approve/dismiss per card ([slack catch up](https://slack.com/blog/news/slack-activity-triage-for-notifications)).
